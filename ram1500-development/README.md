## Engineering deliverables / acceptance gates

1. **Reproducible log decoder:** decode entire Q-logs/R-logs, schema-version pinned; produce time-aligned vehicle, command, radar, camera, model, driver-monitoring, and fault streams. Export summary and machine-readable timelines. Verify units, field definitions, sample timing, and missing data.
2. **Vehicle interface audit:** inspect RAM_1500_5TH_GEN interface/controller, DBC messages, EPS behavior, permitted actuation and stop-to-steer operation. Self-parking proves low-speed steering actuator capacity, not that the openpilot LKAS authorization path operates at zero speed.
3. **Driving behavior replay:** replay captured telemetry into the unmodified baseline, establish lateral error and event distributions. Inspect segment 2 near +171 seconds.
4. **Design proposals and tests:** evaluate control improvements using deterministic replay and unit tests. Keep safety and actuator constraints; do not infer successful behavior from simulation alone.
5. **Zero-speed engagement and destination navigation:** feature exploration separated from baseline. Identify whether supported vehicle integration and reliable maneuver planning are feasible. Do not bypass ECU protections or activate unvalidated behavior.
6. **Reproducible build:** pinned dependencies, CI checks, and release documentation for the exact Comma 3 hardware. Build must be validated before any installer address is issued.
7. **Release acceptance:** independent code review, documented fault handling, regression testing, and controlled testing by qualified operator. Explicitly mark candidate builds *not for public road use* until validated.

## Passive low-speed steering evidence (November 17, 2026)

New read-only tool: `low_speed_report.py`. It consumes the CSV generated by
`analyze_route.py` and aligns `carState.vEgo` with preceding (never future)
`carControl.latActive` and `carOutput.actuatorsOutput.torqueOutputCan`.
It reports separate **exactly recorded 0.0 m/s** and positive crawl-speed bins.
No CAN commands, firmware edits, or vehicle access are involved.

Example **only in a private, schema-compatible checkout** with local logs:
```sh
python3 ram1500-development/analyze_route.py /private/route/*/qlog.zst \
  --expected-segments 51 --focus-seconds 0 --window 999999 \
  --output-prefix /private/ram-full-route
python3 ram1500-development/low_speed_report.py /private/ram-full-route.csv \
  --output /private/ram-low-speed.json
```
Keep all CSVs and real data outputs private. The default `analyze_route.py`
focus near +171 seconds is **not** sufficient evidence about standstill.
The `0.0 m/s` bucket is an observed signal value, not proof of EPS actuation.
A nonzero `carOutput` command is still not a verified transmitted/accepted CAN
command; nonzero EPS feedback likewise requires separate calibration and
source-specific interpretation. Do not mix this fork's newer cereal/opendbc
schema with the November 14 device build (`sunnypilot@1f7233cb`).

**Firmware-specific finding from parked, read-only Comma inspection:** the
installed EPS firmware was `68466110AB`, with `minEnableSpeed=14.5 m/s`,
`minSteerSpeed=0.5 m/s` and `NO_MIN_STEERING_SPEED` unset.
Neither the documented four-firmware exception nor the bus-0 `0x4FF` flag
applies. See `reports/ram-dt-zero-speed-evidence-2026-11-17.md`.
That does **not** establish how the factory self-parking controller reaches
the EPS or whether a separately validated low-speed integration is feasible.

The reporter has synthetic tests in `test_low_speed_report.py`, included
in the GitHub `Ram offline telemetry analyzer tests` workflow. Actual route
numeric results have **not yet** been generated or reviewed.


## Route completeness and replay-input quality gate (November 17)

Before any absolute-time (+171 s) attribution, ensure the input logs are from
**one route**, use **one** of qlog or rlog, and cover the **independently known**
segment range. Previously, a missing first or middle segment could silently
produce the wrong route-relative timestamp, and mixing Q- and R-logs could
count overlapping events twice. The new `route_integrity.py` refuses missing,
duplicate, unreadable, empty, mixed-kind and mixed-route inputs. Reports omit
private route identifiers and paths. This is a **file-level check**, not proof
that each compressed log is decodable.

For the November 14 51-segment route (run only against **private** files):
```sh
python3 ram1500-development/route_integrity.py \
  --kind qlog --expected-segments 51 /private/route/*/qlog.zst
python3 ram1500-development/analyze_route.py /private/route/*/qlog.zst \
  --expected-segments 51 --focus-seconds 171 --window 30 \
  --output-prefix /private/ram-171
```

The `analyze_route.py` CLI now requires `--expected-segments` and fails
closed before decoding on invalid input; its JSON summary records the
non-identifying integrity result. Supply the true count from route metadata;
do **not** substitute the number of downloaded files. The same requirement
applies when exporting a complete route for `low_speed_report.py`.

Eight independent offline fixture tests passed locally for this input gate.
No changes to vehicle control software or Comma installation were made.


## Steering-alert temporal integrity update (November 17, 2026, late evening)

`steering_saturation_report.py` now separately evaluates command and EPS-motor
feedback at each alert's exact monotonic timestamp using **past-only**, age-bounded
joins. The previous report attached command/feedback to a controller sample,
which could itself be up to 150 ms older than the alert: two independently valid
150 ms joins could therefore misattribute a source observation 300 ms old to
the alert. Conversely, it could miss newer output or EPS data recorded between
the controller sample and the alert. New output keys are
`outputTorqueCanAgeAtEventMs` and `steeringTorqueEpsAgeAtEventMs`.
Existing `nearestOutputTorqueCan` and `nearestSteeringTorqueEps` keys now
report **fresh, past-only, as-of-alert** observations. An aged-out source is
null, with the stale age retained so missing evidence is not treated as zero.
The controller-state alert age is unchanged.

Three synthetic regression tests cover compounded staleness, fresh observations
after the latest controller sample, and future-data exclusion. The changes are
analysis-only and do not modify controller, vehicle integration or Panda safety.

To verify from the branch checkout, run:
```sh
python3 -m unittest discover -s ram1500-development -p 'test_steering_saturation_report.py' -v
```

The original November 14 event still requires execution against private,
build-matched logs to determine commanded-output and EPS response values.
Synthetic tests and code reviews cannot establish root cause or deployment fitness.
